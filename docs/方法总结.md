# 英雄联盟历史对局数据导出方法总结

四种获取 LOL 历史对局数据的方法，2026年6月实测。

> ⚠️ **注意**: 本工具 `lolhistory` 当前版本已移除方法一和方法二的代码实现（归档至 `assets/_lcu.py`），目前仅支持方法三（WeGame API）。以下方法一和方法二的介绍作为技术文档完整保留，供未来恢复或其他项目参考。

---

## 方法一：LCU API 直读（~100 场）

### 原理

英雄联盟客户端运行时在 `127.0.0.1` 上启动一个本地 HTTPS 服务（LCU API），通过 lockfile 中的端口和认证令牌即可访问。

### 实现流程

1. **获取 lockfile 凭据** — Lockfile 格式为 `进程名:PID:端口:密码:https`，每次客户端重启后端口和密码都会变化。

   **自动发现策略（4 级 fallback）：**

   | 优先级 | 策略 | 说明 |
   |:---:|------|------|
   | 1 | 显式路径 | 用户通过 `--lockfile PATH` 直接指定 |
   | 2 | 游戏目录搜索 | 通过 `--game-dir` 指定，搜索 `Game/`、`TCLS/`、`LeagueClient/` 子目录 |
   | 3 | 已知路径扫描 | `%LOCALAPPDATA%/Riot Games/Riot Client/Config/lockfile` + 多个盘符下的 `Riot Games/`、`英雄联盟/`、`腾讯游戏/英雄联盟/` 目录 |
   | 4 | 进程命令行提取 | `wmic PROCESS WHERE "name='LeagueClientUx.exe'" GET commandline` 或 `Get-CimInstance Win32_Process`（PowerShell），正则提取 `--app-port=(\d+)` 和 `--remoting-auth-token=([\w\-]+)` |

   - **国际服**：`<安装目录>/lockfile` 直接读取，内容完整
   - **国服（WeGame）**：lockfile **文件存在但通常为空**（0字节），必须走策略4（进程命令行提取）

   > ⚠️ **关键陷阱**：`%LOCALAPPDATA%/Riot Games/Riot Client/Config/lockfile`（端口 9918）是 **Riot Client** 的 lockfile，**不能**用于访问 LCU API！LCU 的 lockfile 位于游戏安装目录下。

2. **认证**：以 `riot:<password>` 做 Basic Auth（`base64.b64encode(f"riot:{password}".encode()).decode()`），请求 LCU API。

   **HTTP 客户端关键配置**：
   - `verify=False` + `urllib3.disable_warnings()` — 绕过自签名证书
   - 重试策略：`Retry(total=3, backoff_factor=0.5, status_forcelist=[429, 500, 502, 503, 504])` — 应对间歇性网络抖动
   - 超时：15 秒

3. **获取 PUUID**：`GET /lol-summoner/v1/current-summoner`

4. **拉取对局列表**：`GET /lol-match-history/v1/products/lol/{puuid}/matches?begIndex=0&endIndex=100`

   - **分页行为**：`begIndex`/`endIndex` 参数**不完全生效**——服务端每次返回的数据量由客户端缓决定，不受请求参数控制。通常以 100 为单位递增请求，直到返回的列表中无新 gameId 为止。
   - **分页耗尽判定**：当某一页的 gameId 全部已存在于已收集集合中（`new_count == 0`），说明分页已耗尽。

   > ⚠️ **响应双格式兼容**：LCU 对局列表端点可能返回两种 JSON 格式，实现时**必须同时处理**：
   > - `{"games": [...]}` — 直接数组包装
   > - `{"games": {"games": [...]}}` — 双层嵌套

5. **获取详情**：`GET /lol-match-history/v1/games/{gameId}` 逐场查询

   **参与者匹配（`_find_participant`）**：对局详情数据中定位本局玩家需兼容两种格式：

   | 格式 | 玩家信息位置 | 游戏数据位置 | 关联方式 |
   |------|------------|------------|---------|
   | 旧格式 | `participantIdentities[].player`（含 puuid/summonerName/championId） | `participants[]`（含 stats） | 通过 `participantId` 关联合并 |
   | 新格式 | `participants[]` 中直接嵌入 `puuid`/`summonerName` | 同一 `participants[]` 条目中的 `stats` 子对象 | 无需关联 |

   **其他解析兼容**：
   - **位置解析**：优先 `teamPosition` 字段 → 回退 `timeline.lane` → 回退 `timeline.role`
   - **名称解析**：优先 `summonerName` → 回退 `gameName#tagLine`（Riot ID 格式）

6. **导出**：JSON（原始数据）+ CSV（UTF-8 BOM，Excel 兼容）

### 核心端点

| 端点 | 用途 |
|------|------|
| `/lol-summoner/v1/current-summoner` | 当前召唤师信息（PUUID） |
| `/lol-match-history/v1/products/lol/{puuid}/matches` | 对局列表（分页参数无效） |
| `/lol-match-history/v1/games/{gameId}` | 单场对局详情 |
| `/lol-game-data/assets/v1/champion-summary.json` | 英雄 ID→名称映射 |

### 结果

| 指标 | 值 |
|------|-----|
| **数量上限** | ~100 场 |
| **依赖条件** | 客户端必须运行且已登录 |
| **国服特殊** | 反作弊可能拦截非白名单进程（HTTP 403），三种绕过方法见下 |

### 国服 403 反作弊拦截 — 三种绕过方法

国服反作弊系统会拦截非白名单进程对 LCU API 的 HTTPS 请求，返回 HTTP 403。

| 方法 | 操作 | 原理 |
|------|------|------|
| **A. 重命名 python.exe**（推荐） | `copy .venv\Scripts\python.exe .venv\Scripts\RiotGamesApi.exe`，然后用 `RiotGamesApi.exe -m lolhistory --method lcu` | 反作弊白名单基于进程名匹配，`RiotGamesApi.exe` 在白名单中 |
| **B. 从游戏目录运行** | 将 `python.exe` 复制到英雄联盟安装目录下，从该目录执行 | 反作弊对游戏目录下的进程放宽限制 |
| **C. 改配置切测试服** | 编辑 `TCLS/config/dirserver.xml` 切换到测试服，登录后再改回正式服 | 测试服反作弊策略较宽松，不拦截 API 请求 |

> 方法 A 最简单可靠，只需复制一次 `python.exe` 并重命名即可永久使用。

## 方法二：LCU API + 客户端缓存（~200 场）

### 原理

LCU API 的 `gameCount` 不是固定值——随着客户端运行时间增长和用户在客户端内向下滚动历史对局页面，本地缓存会逐步加载更多对局数据。

### 实现流程

1. **初始拉取**：`GET /lol-match-history/v1/products/lol/{puuid}/matches?begIndex=0&endIndex=100` 获取当前缓存中的对局，记录 `gameCount`
2. **触发缓存扩展**：保持客户端运行，在客户端生涯 → 对局记录页面**反复向下滚动**，每次滚动到底部会触发客户端向后端请求并缓存更多历史对局
3. **监控增长**：每隔几分钟请求 `begIndex=0&endIndex=0`（仅获取元数据），观察 `gameCount` 是否增长
4. **稳定后全量导出**：当 `gameCount` 连续多次不再增长时（通常意味着客户端缓存已达到极限），重新请求 `begIndex=0&endIndex=<gameCount>` 获取全部数据
5. **分页耗尽判定**：当前页返回的所有 gameId 均已在已收集集合中（`new_count == 0`），停止分页

> **原理**：客户端本地的对局缓存是一个有限的滑动窗口，每次滚动触发 LRU 加载。当窗口滑到尽头时 `gameCount` 停止增长，此时即为可获取的最大值。该上限由客户端配置决定，通常为 ~200 场。

### 结果

| 指标 | 值 |
|------|-----|
| **数量上限** | ~200 场 |
| **依赖条件** | 客户端需长时间运行并手动滚动历史页面 |
| **字段** | 同方法一 |

## 方法三：WeGame API（~500 场）

### 原理

WeGame 助手页使用的后端 API，数据存储在腾讯服务端，比 LCU 客户端缓存更全。通过 Cookie 认证，无需客户端运行。

### 核心端点

| 端点 | 用途 | account_type | id 类型 |
|------|------|:---:|:---:|
| `GetBattleList` | 分页获取对局列表（基础 KDA/位置/输赢） | `1` | puin（数字 UID） |
| `GetBattleDetail` | 单局完整详情（10 人装备/符文/ban） | `2` | openid（Base64） |

### 实现流程

1. **获取 Cookie**（推荐一键抓包）：

   **🆕 方法 3a：一键抓包（推荐）**
   ```bash
   # 首次使用需安装 mitmproxy 根证书（仅需一次）
   python -m lolhistory --install-cert
   # 一键抓包
   python -m lolhistory --capture-cookies
   ```
   代理自动启动 → 登录 WeGame → Cookie 自动捕获并保存为 `cookies.json`。
   
   > **原理**：内嵌 mitmproxy HTTP 代理 + Windows 系统代理，拦截 WeGame QBCore 的 HTTPS 请求。登录时 WeGame 自动发送含 Cookie 的 API 请求，无需手动导航到对局记录页。
   > **依赖**：需要 `pip install mitmproxy`（仅首次）
   > **注意**：WeGame QBCore 使用**逗号**分隔 Cookie（非标准的分号），解析时需兼容

   **方法 3b：从抓包文件提取**
   ```bash
   python -m lolhistory --extract-cookies
   ```
   从 Fiddler/Charles/浏览器导出的 HAR/Raw/cURL 文件中提取 Cookie，自动扫描 `wegame-api-export/` 目录。

   **必需 Cookie**：`puin`、`pkey`、`tgp_biz_ticket`、`tgp_id`

2. **发现 openid**：先用 `account_type=1` 调用 `GetBattleDetail`，从响应自动提取；或 `--openid` 手动指定

3. **分页拉取列表**：`GetBattleList`，每页最多 10 条，offset 递增至返回空（上限 ~500）

4. **（可选）获取详情**：`--detailed` 模式逐场调用 `GetBattleDetail`，获取 10 人装备/符文/召唤师技能/ban 位

5. **导出**：JSON + CSV（中文表头，UTF-8 BOM）

### 运行命令

```bash
# 基本用法
python wegame_fetcher.py --cookies cookies.json

# 指定格式和数量
python wegame_fetcher.py --cookies cookies.json -f csv -n 500

# 含完整详情
python wegame_fetcher.py --cookies cookies.json --detailed

# 命令行传参
python wegame_fetcher.py --puin <puin> --pkey "<pkey>" --tgp-biz-ticket "<ticket>" --tgp-id <id>
```

### 结果

| 指标 | 值 |
|------|-----|
| **数量上限** | ~500 场 |
| **依赖条件** | 仅需有效 Cookie，无需客户端 |
| **段位数据** | ✅ 每局段位历史 |
| **详情数据** | ✅ 10 人装备/符文/召唤师技能/ban 位（`--detailed`） |

### API 限制

- `count` 参数最大 10（超过返回错误码 `8000002`）
- offset ≥ 500 返回空
- Cookie 可能过期，需重新获取

## 方法四：Riot Games 官方 API（国服不可用 ❌）

### 原理

Riot 官方提供开发者 API，通过 API Key 访问全球路由。

### 不可用原因

国服由腾讯独立运营，使用独立的平台 ID（`HN1`）和基础设施：

- 国服 PUUID 格式与标准 Riot API 不兼容，所有全球路由（americas/asia/europe/sea）返回 `400 - Exception decrypting puuid`
- 通过 Riot ID 查询返回 `404 - Data not found`
- 腾讯后端（`hn1-k8s-sgp.lol.qq.com`）使用独立认证体系，非公开 API

### 适用场景

仅限非国服地区（NA/EUW/KR 等）的 Riot 直营服务器。

## 四种方法对比

| | LCU API | LCU + 缓存 | WeGame API | Riot API |
|------|:---:|:---:|:---:|:---:|
| **数量上限** | ~100 | ~200 | ~500 | 全量（非国服） |
| **需要客户端** | ✅ 运行中 | ✅ 运行中 | ❌ | ❌ |
| **国服可用** | ✅ | ✅ | ✅ | ❌ |
| **段位数据** | ❌ | ❌ | ✅ | ✅ |
| **装备/符文详情** | 基础 | 基础 | ✅ (--detailed) | ✅ |
| **字段数** | ~50 | ~50 | ~38 (+详情) | ~100+ |

### 选用建议

| 场景 | 推荐方法 |
|------|----------|
| 客户端在线，快速导出 | 方法一（LCU API）* |
| 客户端在线，要更多场次 | 方法二（LCU + 缓存）* |
| 需要最多场次 / 段位历史 / 装备符文详情 | 方法三（WeGame API）✅ 本工具支持 |
| 非国服，需要全量历史 | 方法四（Riot API） |
| 国服，需要超过 500 场 | 目前无可行方案 |

> \* 方法一和方法二在本工具中已弃用，代码归档至 `assets/_lcu.py`
